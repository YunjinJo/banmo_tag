# 📝 banmo_tag 패치 노트 (Changelog)

이 문서는 banmo_tag 크롬 확장 프로그램의 버전별 기능 추가, 변경, 버그 수정 내역을 기록하는 공식 패치 노트입니다.
각 버전의 변경 내역은 연관된 테스트 케이스([TEST_CASES.md](TEST_CASES.md)) 및 자동화 테스트 러너([run-tests.ps1](../tests/run-tests.ps1), [test-runner.html](../tests/test-runner.html))와 1:1로 매핑되어 검증됩니다.

## [Unreleased]

> 아직 릴리스하지 않은 변경 사항입니다. 새 버전을 릴리스할 때 `npm run bump -- X.Y.Z` 를 실행하면 이 항목이 그 버전의 내용이 됩니다.

### 🚀 Added (새로운 기능)
- **파이어폭스 지원 (Firefox 140 이상)**: 같은 `extension/` 폴더와 같은 zip 으로 크롬과 파이어폭스를 함께 지원합니다.
  - `manifest.json`: 크롬은 `background.service_worker`, 파이어폭스는 `background.scripts`(이벤트 페이지, `shared.js` → `background.js` 순서)를 씁니다. 파이어폭스 ID(`banmo_tag@yunjinjo`), 최소 버전, 데이터 수집 없음(`data_collection_permissions: none`)을 적었습니다.
  - `background.js`: `importScripts` 가 있을 때(크롬)만 `shared.js` 를 불러옵니다.
  - **팝업 [↗] 새 탭에서 열기**: 팝업 화면을 일반 탭에서 엽니다. [현재 탭에서 가져오기]·[뺀 멤버 정리]는 열 때 보고 있던 X 탭을 대상으로 동작합니다.
  - **파이어폭스 팝업 우회**: 파이어폭스는 팝업에서 파일·색상 선택 창이나 다운로드를 열면 팝업이 닫혀 버립니다(Firefox 버그 1292701). 그래서 파이어폭스 팝업에서는 내보내기, 가져오기, 색상 선택을 누르면 같은 화면이 새 탭에서 열리고, 팝업에 그 이유를 안내합니다.
  - **x.com 접근 권한 안내**: 파이어폭스에서 사용자가 x.com 접근을 허용하지 않았으면 팝업에 안내와 [x.com 접근 허용] 버튼을 보여 줍니다(크롬은 설치할 때 허용되므로 표시되지 않음).
- **파이어폭스 검사·테스트**: CI 정적 검사에 Mozilla 부가 기능 사이트와 같은 검사(`web-ext lint`)를 추가하고, 실제 Firefox 에 임시 설치해 19가지 동작을 확인하는 `npm run test:firefox` 와 CI 작업을 추가했습니다.
- **팝업 화면 새 디자인 (`popup.html`, `popup.js`)**
  - **[리스트 | 기본 스타일 | 도움말] 탭**으로 화면을 나눴습니다. 탭은 ← → Home End 키로도 오갈 수 있습니다.
  - **리스트 카드**: 실제 배지 모양, 멤버 수, "강조 · 개별 스타일 · @a, @b 외 N명" 요약을 보여 줍니다. **이름순 / 멤버 수** 정렬을 고를 수 있고 선택은 저장됩니다.
  - **리스트 설정 창 (아래에서 올라오는 시트)**: 카드를 누르면 배지 색(빠른 선택 6색 + 직접 고르기), 글자 크기·폰트·글자 색, 타임라인 표시(배지만 / 강조 / 흐리게), 실제와 같은 트윗 미리보기, 멤버 보기·개별 삭제, 리스트 삭제를 한곳에서 합니다. Esc·닫기·바깥을 누르면 닫히고 포커스는 카드로 돌아갑니다.
  - **⋯ 메뉴**: 백업 내보내기·가져오기와 초기화를 머리글의 ⋯ 메뉴로 옮겼습니다(초기화는 빨간색).
  - 버튼 이름을 **[현재 탭에서 가져오기]**, **[뺀 멤버 정리]**, **[+ 추가]** 로 짧게 바꿨습니다. 상태 메시지는 어느 탭·창에서도 보이도록 화면 위에 뜹니다.
  - 확인 상자·가져오기 선택은 화면 가운데 카드로 뜨고, 떠 있는 동안 뒤 화면은 조작되지 않습니다. 닫으면 포커스가 원래 버튼으로 돌아갑니다.
  - 파이어폭스에서 시트의 [다른 색]을 누르면 새 탭 화면에서 같은 리스트의 설정 창이 열린 채로 시작합니다.
- **화면 테마: 시스템 / 라이트 / 다크 (`theme.js`, `uiSettings`)**: 기본은 운영체제의 라이트/다크 설정을 따르고, [기본 스타일] 탭에서 직접 고를 수 있습니다. 색은 CSS 변수(토큰)로 정의했고 본문 글자 대비는 4.5:1 이상(WCAG AA)입니다. 고른 테마는 `chrome.storage.local` 의 `uiSettings` 에 저장되며, 팝업을 열 때 깜빡이지 않도록 `<head>` 의 `theme.js` 가 첫 화면 전에 적용합니다.
- **타임라인 배지 개선 (`content.js`, `styles.css`, `splitTimelineBadges`)**
  - 한 사람이 리스트 4개 이상에 속하면 배지 2개만 보이고 나머지는 **+N** 으로 묶습니다. +N 에 마우스를 올리면 모든 리스트 이름이 보입니다.
  - 긴 리스트 이름은 말줄임(…)으로 줄이고, 배지에 마우스를 올리면 전체 이름이 보입니다.
  - **흐리게** 모드는 트윗 전체 대신 프로필 사진·본문·미디어·버튼만 흐리게 해서, 이름과 배지는 또렷하게 읽힙니다. 흐리게 할 부분을 찾지 못하면 예전처럼 트윗 전체를 흐리게 합니다.

### 🛠️ Changed (변경 및 개선)
- **Claude Code 작업 설정 (`CLAUDE.md`, `.claude/`)**: 작업 규칙·명령·코드 규칙을 담은 `CLAUDE.md`, main 직접 커밋·push 를 막는 훅과 `.js` 수정 후 ESLint 훅, 읽기 전용 명령 허용 목록, 스킬 `/banmo-pr`(브랜치→PR) · `/banmo-release`(릴리스 준비) · `/x-snapshot`(실제 X 화면 스냅샷)을 추가했습니다.
- **릴리스는 GitHub 에서 직접 (`.github/workflows/ci.yml`)**: CI 가 더 이상 GitHub Release 와 배포 zip(Artifacts)을 만들지 않습니다. CI 는 검사·테스트·zip 패키징 확인만 하며 저장소 쓰기 권한도 없습니다. 릴리스 방법은 README 의 "릴리스 (수동)" 참고.
- **CHANGELOG `[Unreleased]` 항목**: 릴리스 전 변경 사항은 이 항목에 모으고, `npm run bump -- X.Y.Z` 가 이 항목을 새 버전 항목으로 바꿉니다. 버전 올리기 스크립트는 모든 변경을 계산한 뒤 한꺼번에 저장하도록 바꿔, 중간에 실패해도 `manifest.json` 만 바뀌는 일이 없습니다.

- **정적 검사 추가 (`scripts/validate.js`)**: `popup.html` 의 `<head>` 첫 스크립트가 `theme.js` 인지, 흐리게 모드 선택자가 `shared.js` 와 `styles.css` 에서 같은지 확인합니다. 배포 zip 과 CI 패키징 확인에 `theme.js` 를 추가했습니다.

### 🐛 Fixed (버그 수정)
- **배포 zip 의 폴더 경로가 `\` 로 저장되던 문제 (`scripts/build.ps1`)**: Windows PowerShell 5.1 의 `Compress-Archive` 가 `icons\icon16.png` 처럼 `\` 를 써서, 다른 도구나 Chrome 웹 스토어에서 `icons` 폴더로 인식되지 않을 수 있었습니다. zip 표준대로 `icons/icon16.png` 형식으로 만들고, CI 가 아이콘 포함 여부와 `\` 경로를 검사합니다.

## [v1.6.0] - 2026-11-05

### 🚀 Added (새로운 기능)
- **리스트별 배지 글자 스타일 (`list.style`, `normalizeListStyle`, `getEffectiveBadgeSettings`, `setListStyle`)**: 팝업에서 리스트를 펼치면 그 리스트 배지의 글자 색상·크기(8~20px)·폰트를 따로 정할 수 있습니다. 바꾼 항목만 리스트에 저장되고, 나머지 항목은 공통 설정을 따릅니다. 편집란에 실제 배지와 같은 미리보기가 있고, 따로 설정한 리스트에는 목록에 "🎨 개별 스타일"이 표시됩니다. [공통 설정 따르기]로 되돌릴 수 있습니다.
- **모든 리스트에 한 번에 적용**
  - 공통 설정의 **[모든 리스트에 적용]**: 리스트별 글자 스타일을 모두 지워 모든 리스트가 공통 스타일을 쓰게 합니다. 개별 스타일을 쓰는 리스트 수를 함께 보여 주고, 지우기 전에 확인을 받습니다.
  - 리스트별 **[이 스타일을 모든 리스트에 적용]**: 그 리스트의 스타일을 공통 설정으로 만들고 다른 리스트의 개별 스타일을 지웁니다.

### 🛠️ Changed (변경 및 개선)
- **배지 스타일 설정 → "모든 리스트 공통"**: 기존 배지 스타일 설정은 모든 리스트의 기본 스타일이 됩니다. 이전 버전의 데이터와 백업 파일은 그대로 사용할 수 있습니다(개별 스타일이 없으면 지금과 똑같이 보임).
- **리스트 스타일을 바꾸면 그 리스트 멤버의 트윗만 다시 그림**: 배지 매핑에 리스트 스타일을 넣어, 바뀐 리스트의 배지만 다시 그립니다.
- **백업**: 리스트별 글자 스타일도 내보내고 가져옵니다. 병합 가져오기에서는 기존 리스트의 스타일을 유지합니다.
- **팝업을 열 때 공통 설정을 먼저 읽고 리스트를 그림**: 리스트별 편집란이 처음부터 저장된 공통 설정 기준 값을 보여 줍니다.

### 🧪 Tests (테스트 추가)
- **TS-25** 리스트별 글자 스타일 7건: 단위 테스트 90건 → **97건**.
- **E2E 7건 추가 (24건 → 31건)**: 팝업에서 리스트별 크기·색상·폰트 저장과 되돌리기, 범위를 벗어난 크기 거부, 두 가지 "모든 리스트에 적용", 팝업을 열 때 공통 설정 값 표시, 타임라인에서 리스트별 스타일 적용(미니 배지 포함)과 바뀐 리스트만 다시 그리기.

## [v1.5.0] - 2026-11-05

### 🚀 Added (새로운 기능)
- **멤버 목록 교체 동기화 (`applyListReplace`, 팝업 `[🔄 멤버 목록 교체 동기화]`)**: X 리스트에서 뺀 멤버가 계속 남던 문제(개선 과제 6번)를 해결합니다. 멤버 화면을 끝까지 스크롤한 뒤 누르면, 이번 방문에서 화면에 나타난 멤버(가상 스크롤로 사라진 멤버 포함)로 저장 목록을 교체합니다. 삭제·추가될 인원과 삭제될 핸들을 먼저 보여 주고 확인을 받으며, 절반 이상 삭제되면 강하게 경고합니다. 색상·모드·`listId`는 유지됩니다.
- **X 화면 구조 변화 경고 (`diagnoseStructure`, `getStructureWarnings`)**: 사용자 정보는 보이는데 확장 프로그램이 기대하는 구조(`UserCell`, `data-testid="tweet"`, `User-Name`)가 없는 상태가 2.5초 이상 계속되면 기록하고, 팝업 맨 위에 "X 화면 구조가 바뀌었을 수 있습니다" 경고를 띄웁니다. 정상 화면을 다시 보면 자동으로 사라지며, 2주가 지난 경고는 표시하지 않습니다. 저장하는 것은 영역·안내 문구·시각뿐이며 URL이나 화면 내용은 저장하지 않습니다.

### 🛠️ Changed (변경 및 개선)
- **리스트가 바뀌면 바뀐 사람의 트윗만 다시 그림 (`diffHandleMaps`, `isTweetAffected`)**: 멤버 화면을 스크롤하며 자동 저장될 때마다 열려 있는 모든 X 탭이 배지를 전부 지우고 다시 그리던 것을, 배지 표시가 달라진 핸들의 트윗만 다시 그리도록 바꿨습니다. 배지 스타일 설정 변경은 모든 배지에 영향을 주므로 계속 전체를 다시 그립니다.
- **개발 도구**: ESLint(`no-undef` 등, `shared.js` 전역 함수 자동 등록), Dependabot(GitHub Actions·npm 주간 업데이트 PR), Playwright E2E 테스트(실제 확장 프로그램을 Chromium 에 로드해 팝업·content script·background 검사), 버전 올리기 스크립트(`npm run bump -- X.Y.Z`)를 추가했습니다. `scripts/build.ps1`은 Node.js 가 있으면 정적 검사와 ESLint 도 함께 실행합니다.
- **CI/CD**: 정적 검사 단계에서 ESLint 를 실행하고, Ubuntu 에서 Playwright E2E 테스트 단계를 추가했습니다. 릴리스는 정적 검사·E2E·Windows 테스트·빌드가 모두 통과해야 만들어집니다.

### 🐛 Fixed (버그 수정)
- **배지 스타일 설정을 키보드로 열 수 없던 문제**: 머리글이 `div role="button"`이라 Tab 으로 갈 수 없었습니다. `<button>`으로 바꾸고, 팝업의 버튼·입력란에 키보드 포커스 표시를 추가했습니다.
- **직접 추가에서 "X"·"Home"·"리스트" 같은 이름을 쓸 수 없던 문제 (`getManualListNameError`, `manual` 표시)**: 시스템 단어 차단은 자동 수집에만 적용합니다. 직접 추가로 만든 리스트에는 `manual: true`를 붙여, 데이터를 정리할 때 시스템 단어 이름이라는 이유로 지워지지 않게 했습니다(백업에도 보존). 이름은 1~50자.
- **X 의 화면 읽기용 제목이 리스트 이름으로 잡힐 수 있던 문제 (`cleanListName`)**: `타임라인: 리스트 멤버` 같은 제목에서 `타임라인`이 리스트 이름이 될 수 있었습니다. `타임라인:`/`Timeline:` 접두사를 지우고 `타임라인`/`Timeline` 단독은 시스템 단어로 처리합니다.

### 🧪 Tests (테스트 추가)
- **TS-21~24** (`applyListReplace`, `diffHandleMaps`/`isTweetAffected`, `diagnoseStructure`/`getStructureWarnings`, `manual` 리스트) 및 TS-13 보강: 단위 테스트 73건 → **90건**.
- **E2E (Playwright) 24건**: 멤버 자동 수집·추천 제외, 메인 → 멤버 화면 이름 캐시, 배지·강조·인용 미니 배지, 바뀐 트윗만 다시 그리기, DOM 재사용, 교체 동기화, 구조 변화 경고 기록/해제, 팝업 키보드 접근·직접 추가("X" 이름 포함)·확인 상자·백업 내보내기/덮어쓰기·구조 경고 표시, 팝업 ↔ X 탭 연동. 테스트용 X 화면은 `tests/fixtures/synthetic/`(합성), 실제 화면 스냅샷은 `tests/fixtures/real/`에 추가하면 자동 검사됩니다.

## [v1.4.1] - 2026-11-04

### 🐛 Fixed (버그 수정)
- **리스트 이름 캐시가 자동 수집 때 채워지지 않던 문제 (`scrapeListMembers`)**: 리스트 메인 페이지는 자동 수집 차단 검사에서 바로 끝나 이름을 한 번도 읽지 않았습니다. 이제 차단 검사 전에 이름을 읽어 세션 캐시를 채우므로, 이후 멤버 화면에서 `리스트 (ID)` 임시 이름 대신 실제 이름으로 저장됩니다. 표시 이름 등이 잡힐 수 있는 TopNavBar 추정 이름은 캐시하지 않습니다.
- **실제 리스트 이름 뒷부분이 잘리던 문제 (`cleanListName`)**: `Core Members`→`Core`, `우리팀 리스트 멤버`→`우리팀`, `연락처 me@site`→`연락처 me`로 잘리던 문제를 수정했습니다. 시스템 접두사/접미사는 구분자(`-`, `·`, `•`, `:`, `|`)가 있을 때만, 끝의 `@핸들`은 앞에 공백이 있을 때만 지웁니다.
- **정제 과정에서 서로 다른 리스트가 합쳐지던 문제 (`sanitizeListsObject`)**: 정제한 이름이 같아도 `listId`가 다르면 `resolveListKey`와 같은 규칙(`A (1234)`)으로 분리합니다. 원래 그 이름을 쓰던 리스트가 이름을 유지하며, 각 리스트의 멤버·색상·모드도 보존됩니다.
- **백업 병합 시 동명 리스트가 합쳐지던 문제 (`mergeImportedLists`)**: 병합 가져오기도 `listId` 기준으로 매칭합니다. 같은 `listId`는 이름이 달라도 한 리스트로 합칩니다.
- **직접 추가가 기존 리스트의 색상·모드를 초기화하던 문제 (`applyManualAdd`)**: 이미 있는 리스트에 추가하면 멤버만 합치고 색상·모드는 그대로 둡니다.
- **X가 아닌 탭에서 엉뚱한 안내가 나오던 문제 (`getSyncTabError`)**: `tabs` 권한이 없어 `url`이 비어 있는 탭은 "X(Twitter) 페이지가 아닙니다"로 안내합니다.
- **인용 트윗에 미니 배지가 붙지 않던 문제 (`getBadgeAnchor`)**: 이름에 `<a>` 링크가 없으면 이름 영역에 직접 배지를 붙입니다.
- **추천 계정 필터가 너무 넓던 문제 (`isExcludedUserCell`, `isRecoLabel`)**: 목록 전체가 아니라 셀 바로 앞 구간의 제목만 검사하고, `aria-label`·제목은 부분 문자열이 아닌 전체 일치(`타임라인: 팔로우 추천`처럼 콜론 접두사 허용)로 비교합니다. 목록 아래쪽 추천 블록 때문에 멤버 전체가 빠지거나, 이름에 `Connect`/`추천`이 들어간 리스트가 막히지 않습니다.

## [v1.1.0] - 2026-09-30

### 🚀 Added (새로운 기능)
- **Import JSON 구조 검증**: 배열이나 비정상 JSON 파일 Import 시 자동 감지 및 차단. 각 리스트 엔트리의 `{color, mode, members}` 구조 자동 보정.
- **팝업 아코디언 상태 유지**: 리스트 내용 변경(멤버 삭제, 색상 변경 등) 시 펼쳐둔 아코디언이 접히지 않고 상태 유지.
- **멤버 핸들 입력 형식 검증**: 수동 추가 시 `@[A-Za-z0-9_]{1,15}` 정규식으로 유효한 트위터 핸들만 허용.

### 🛠️ Changed (변경 및 개선)
- **MutationObserver 자기 트리거 차단**: 배지 주입 등 자체 DOM 변경이 옵저버를 재트리거하던 CPU 과부하 문제를 `isProcessing` 가드 플래그로 원천 차단.
- **URL 변경 감지 최적화**: 모든 DOM 변경에 반응하던 MutationObserver 기반 URL 감지를 `history.pushState`/`replaceState` 인터셉트 방식으로 교체하여 성능 대폭 개선.
- **테스트 2중 실행 제거**: `test-runner.html`에서 DOM 렌더링과 JSON 리포트 생성 시 테스트가 2회 실행되던 문제를 1회 실행 후 결과 재사용으로 변경.
- **Export 대용량 지원**: `data:` URI 방식을 `Blob + URL.createObjectURL`로 교체하여 대용량 백업 파일 다운로드 지원.
- **CSS 명시도(Specificity) 강화**: Twitter의 공격적인 CSS에 의해 배지 스타일이 덮어쓰여지지 않도록 `!important` 및 `text-shadow` 적용.
- **뱃지 `✔` 자동 해제**: 동기화 후 3초 뒤 아이콘 뱃지 자동 초기화.

### 🐛 Fixed (버그 수정)
- **[Critical] `storage.clear()` 전체 데이터 삭제 → 리스트만 초기화**: 초기화 버튼이 리스트 외의 모든 확장 프로그램 데이터까지 삭제하던 치명적 버그 수정. `chrome.storage.local.set({ lists: {} })`로 교체.
- **[Critical] Sanitize → onChanged → loadLists 무한 루프 차단**: 데이터 정제 쓰기가 `onChanged` 리스너를 통해 `loadLists()`를 무한 재호출하던 문제를 `isSelfWriting` 플래그로 차단.
- **[Critical] 데이터 로드 전 타임라인 처리 레이스 컨디션 해결**: 스토리지 비동기 로드 완료 전에 빈 데이터로 트윗을 `processed` 마킹하여 배지가 누락되던 문제를 `clearProcessedStyles()` 선행 호출로 해결.
- **[Critical] 메시지 채널 누수 수정**: `background.js`에서 `return true`가 모든 메시지에 대해 실행되어 미응답 메시지 포트가 서비스 워커 종료까지 열려있던 누수 수정.
- **[High] 스토리지 저장 실패 무시 수정**: `chrome.storage.local.set` 콜백에서 `chrome.runtime.lastError` 미확인으로 실패해도 성공 응답하던 문제 수정.
- **[High] 데드 코드 정리**: `updateFloatingBtn` 시그니처 불일치 호출 제거, 미작동 `showToast` 호출 제거, `debounce` 내 불필요한 `clearTimeout` 제거.
- **[Medium] `manifest.json`에 `run_at: document_idle` 명시** 추가.
- **[Medium] 밝은 배경색 뱃지에서 흰색 텍스트 가독성 확보** (`text-shadow` 적용).
