# 🧪 banmo_tag 테스트 케이스 명세서 (Test Specification)

본 문서는 banmo_tag 크롬 확장 프로그램의 버전별 기능 및 버그 수정 사항에 대응되는 **자동화 테스트 스위트**와 **수동 QA 테스트 시나리오**를 기록하고 관리하는 공식 문서입니다. [CHANGELOG.md](CHANGELOG.md)의 모든 기능 및 패치 내역은 본 명세서의 테스트 항목과 1:1로 대응됩니다.

---

## 1. 테스트 실행 방법 (How to Run Tests)

banmo_tag는 별도의 Node.js, Python, 외부 패키지 설치 없이 윈도우 환경에서 즉시 2가지 방식으로 테스트를 실행할 수 있습니다.

### 방법 A: CLI 헤드리스 브라우저 자동 검증 (추천 / CI·CD 연동 가능)
- **명령 프롬프트/파워셸**:
  ```powershell
  powershell -ExecutionPolicy Bypass -File .\tests\run-tests.ps1
  ```
- **탐색기 원클릭**:
  - `tests\run-tests.bat` 파일을 더블 클릭
- **GitHub Actions**: `main` 브랜치 push 및 PR 마다 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml)이 정적 검사([`scripts/validate.js`](../scripts/validate.js))·ESLint, E2E(Ubuntu), 같은 단위 테스트(Windows 러너)를 실행하고 배포 zip 을 빌드합니다.

### 방법 C: Playwright E2E (실제 확장 프로그램, Node.js 필요)
- `npm ci` 와 `npx playwright install chromium` 을 한 번 실행한 뒤 `npm test`.
- [`tests/e2e/`](../tests/e2e/)의 테스트가 실제 `extension/` 폴더를 Chromium 에 로드하고, `x.com` 요청에는 [`tests/fixtures/`](../tests/fixtures/README.md)의 HTML 로 응답해 팝업·content script·background 를 함께 검사합니다. `shared.js` 단위 테스트(`test-runner.html`)도 이 안에서 함께 실행됩니다.
- **작동 원리**:
  1. 시스템에 설치된 Chrome 또는 Edge의 Headless 모드(`--headless=new --dump-dom`)를 백그라운드로 실행.
  2. `test-runner.html`이 [`shared.js`](../extension/shared.js)를 직접 로드하여 **97개 단위 테스트**를 브라우저 환경에서 고속 실행(평균 10~15ms).
  3. JSON 포맷으로 생성된 결과를 터미널 콘솔에 컬러로 포맷팅하여 출력.
  4. 모든 테스트 통과 시 Exit Code `0`, 실패 시 Exit Code `1` 반환.

### 방법 B: 브라우저 시각적 UI 검증
- [`test-runner.html`](../tests/test-runner.html) 파일을 크롬 또는 엣지 브라우저로 열기(더블 클릭).
- 상단 대시보드 카드(전체/통과/실패/소요시간) 및 아코디언 형태의 직관적인 UI로 실시간 확인 가능.

### [TC-V141] v1.4.1 실제 화면 확인
1. 리스트 메인(`/i/lists/<ID>`)을 연 뒤 "멤버" 화면으로 이동 → 팝업에 `리스트 (<ID>)`가 아닌 실제 이름으로 저장되는지 확인.
2. 리스트 멤버가 인용된 트윗을 찾아 인용 카드 작성자 이름 옆에 미니 배지가 붙는지 확인.
3. 타임라인을 길게 스크롤하며 새로 나타나는 트윗에 배지가 붙고, 다른 작성자 트윗에 이전 배지가 남지 않는지 확인.
4. 팝업에서 리스트 삭제/초기화 시 팝업 안 확인 상자가 뜨는지 확인.

## 3. 수동 QA E2E 테스트 시나리오 (Manual Test Cases)

### [TC-01] 리스트 이름 정제 (내 태그 제거 검증)
- **대응 버전**: v1.0.1
- **목적**: 트위터가 브라우저 타이틀에 덧붙이는 `@내아이디`가 리스트 이름 및 타임라인 뱃지에 노출되지 않는지 확인.
- **사전 조건**: 사용자가 생성한 리스트 페이지 접속 (`https://x.com/i/lists/...`)
- **테스트 절차**:
  1. 트위터에서 내가 만든 리스트(예: `코인 뉴스`)의 멤버 목록 창을 연다.
  2. 확장 프로그램 팝업을 열거나 상단 `[가져오기]`를 누른다.
- **예상 결과**:
  - 리스트 이름이 `코인 뉴스 (@내아이디)`가 아닌 **`코인 뉴스`**로 저장된다.
  - 타임라인 트윗 옆에 붙는 뱃지에도 `코인 뉴스`만 깔끔하게 노출된다.

### [TC-02] 모달 창 뒤 "팔로우 추천" 차단 검증
- **대응 버전**: v1.0.1
- **목적**: 멤버 목록 모달 창이 열렸을 때, 창 뒤편의 타임라인이나 우측 사이드바의 "팔로우 추천" 계정이 섞여 들어가지 않는지 검증.
- **사전 조건**: 트위터 리스트 메인 페이지 접속 후 "구성원 관리" 또는 "멤버" 모달 창 오픈.
- **테스트 절차**:
  1. 리스트 멤버 관리 모달 창(`role="dialog"`)을 띄운다.
  2. 확장 프로그램 팝업을 열고 `[⚡ 현재 열린 트위터 리스트 가져오기]`를 클릭한다.
  3. 저장된 리스트의 멤버 수를 확인하고 클릭하여 펼친다.
- **예상 결과**:
  - 모달 창 내부에 나열된 멤버만 추가되며, 창 뒤편 사이드바의 추천 계정은 단 한 명도 수집되지 않는다.

### [TC-03] 화면 하단 플로팅/알림 완전 비활성화 확인
- **대응 버전**: v1.0.1
- **목적**: 웹서핑 시 화면을 가리던 하단 플로팅 버튼과 토스트 팝업이 뜨지 않는지 확인.
- **사전 조건**: 트위터 리스트 및 타임라인 페이지 탐색.
- **테스트 절차**:
  1. 리스트 페이지(`https://x.com/i/lists/...`)에 접속한다.
  2. 화면을 스크롤하거나 새로고침(F5)을 한다.
- **예상 결과**:
  - 화면 하단 우측에 `⚡ '리스트 ...' 멤버 목록 열기` 플로팅 버튼이 **전혀 나타나지 않는다**.
  - 화면 하단 중앙에 토스트 팝업이 뜨지 않는다.

### [TC-04] 확장 프로그램 아이콘 알림 뱃지 검증
- **대응 버전**: v1.0.1
- **목적**: 멤버 수집 또는 리스트 갱신 시 크롬 확장 프로그램 툴바 아이콘에 시각적 알림이 표시되는지 확인.
- **사전 조건**: 트위터 리스트 페이지 또는 멤버 모달 열람.
- **테스트 절차**:

### [TC-08] 배지 스타일 커스터마이징(`!important`) 및 기본값 복원 검증
- **대응 버전**: v1.2.0 / v1.3.0
- **목적**: 팝업에서 설정한 글자 색상, 글자 크기, 폰트가 `styles.css`의 기본값을 덮어쓰고 실제 트위터 타임라인 배지에 즉시 반영되는지 확인.
- **사전 조건**: 최소 1개의 리스트가 등록되어 있고 타임라인에 배지가 표시된 상태.

  - `[기본값 복원]` 클릭 시 즉시 `#ffffff`, `11px`, 시스템 기본 폰트로 되돌아간다.

### [TC-09] 백업 JSON 가져오기 시 병합(Merge) / 덮어쓰기(Replace) 선택 검증
- **대응 버전**: v1.3.0
- **목적**: 백업 파일을 불러올 때 기존 리스트가 예고 없이 유실되지 않고 병합 또는 덮어쓰기를 선택할 수 있는지 확인.
- **사전 조건**: 팝업에 기존 리스트 `A`가 등록된 상태 및 리스트 `B`가 담긴 백업 `.json` 파일 준비.
- **테스트 절차**:
  1. 팝업 하단 `[가져오기 (복구)]` 버튼을 눌러 백업 `.json` 파일을 선택한다.
  2. 나타나는 선택 창(`#import-choice`)에서 `[병합]`을 클릭한다.
  3. 다시 같은 파일을 선택하고 이번에는 `[덮어쓰기]`를 클릭한다.
- **예상 결과**:
  - `[병합]` 선택 시 기존 리스트 `A`와 파일의 리스트 `B`가 모두 유지되며, 동일 이름 리스트는 멤버가 합집합으로 병합된다.
  - `[덮어쓰기]` 선택 시 기존 리스트 `A`가 제거되고 백업 파일의 리스트 `B`로만 교체된다.

### [TC-10] 멤버 관리 탭("구성원" vs "추천") 자동 수집 정책 검증
- **대응 버전**: v1.3.0
- **목적**: 리스트 멤버 관리 모달에서 `"구성원"` 탭일 때만 자동 수집되고 `"추천"` 탭이나 `/followers` 화면에서는 수집이 차단되는지 확인.
- **사전 조건**: 트위터 리스트 페이지 접속 후 `구성원 관리` 모달 오픈.
- **테스트 절차**:
  1. 모달의 `"구성원"` 탭에서 스크롤하여 멤버가 자동 수집되는지 확인한다.
  2. 모달 상단 탭을 `"추천(Suggested)"` 탭으로 전환하고 스크롤 및 팝업 `[가져오기]`를 클릭한다.
- **예상 결과**:
  - `"구성원"` 탭에서는 실제 멤버만 정상 수집된다.
  - `"추천"` 탭에서는 자동 수집이 동작하지 않으며, 수동 `[가져오기]` 클릭 시 `"추천" 탭에서는 수집하지 않습니다.` 안내 메시지가 표시된다.
